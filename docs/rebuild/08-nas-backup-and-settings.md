# 08. NASバックアップと設定・復元

更新日: 2026-09-06

## 1. 状態と範囲

[07の状態区分](07-recording-and-workflows.md)に従う。
以下のAccepted以外は、実装に向けたRecommendedまたはOpenである。
本資料は将来設計であり、NAS接続、共有フォルダー、スケジュール、コンテナ、
本番データへの変更を実行する指示ではない。

### Accepted

- バックアップの保存先はNAS。
- 自動バックアップは**配信終了後と1日1回**。
- 日次実行は**午前4時（JST）**を初期値とし、設定から変更できる。
- 自動世代管理は**日次14日分・週次4週分・配信終了後の最新3世代**を初期値とする。
  同じコピーは重複保存せず、実データ量に応じて保持数を変更できる。
- 配信データ・メモ・セット・ルール等を保存し、動画本体と認証情報は別管理にする。
- 手動バックアップを用意し、NAS不通時は転送待ちとして本体側の記録を継続する。
- 本体側のコピー作成・検証とNAS転送・検証を分け、最後にNASへ保存できたデータ時点を表示する。
- 復元は配信外に候補を検証して行う。バックアップ失敗が続いても最後の正常コピーを残す。
- 既存のチャット本文の無期限保存・手動削除、および配信外イベントの記録方針を維持する。

NASの実フォルダー、共有方式、アカウント、空き容量は未確認である。
個人の環境情報を転記して保存先を決めたことにはしない。

## 2. Recommended: コピーを作ってからNASへ保存する

```mermaid
flowchart LR
    DATA[稼働中のデータ] --> SNAP[本体側で整合性の取れたコピーを作成]
    SNAP --> CHECK[復元用データの検証]
    CHECK --> TRANSFER[NASへ転送]
    TRANSFER --> VERIFY[NAS側の内容を検証]
    VERIFY --> DONE[NAS保存完了として一覧に追加]
```

- SQLiteの稼働中DBはローカルの既存 `/app/data` 境界に置く。
- NASには完了したバックアップを保存する。NAS上のバックアップを直接稼働DBとして開かない。
- SQLite Online Backup APIでローカルの新規候補を作り、コピー作成中の
  記録処理への影響を抑える。稼働DB本体やWALを別々の通常コピーで集めない。
- ローカル候補はバックアップ専用の領域で管理し、既存ファイルを上書きしない。
- コピー作成日時、スナップショットが含む最終保存位置、転送完了日時を区別する。
  転送が終わった時刻までのデータが含まれるとは表示しない。
- 転送先では未完了名または未完了ディレクトリを使い、内容の照合が済むまで
  復元可能なバックアップとして公開しない。
- NASへの保存完了後も、一つ前の正常なバックアップを直ちに失わない世代管理を行う。

SQLiteのWALモードにはネットワークファイルシステム上での運用制約がある。
稼働DBの保存と、閉じたバックアップファイルのNAS保管を別の処理にする。
出典: [SQLite Online Backup API](https://www.sqlite.org/backup.html)、
[Write-Ahead Logging](https://www.sqlite.org/wal.html)。

### 配備境界

本体側の候補・転送依頼・結果は既存 `/app/data` 内で扱う案を基本とする。
NAS転送はホスト側の既存NAS連携を利用できるか確認し、転送結果をバックアップIDと
内容の検証結果でアプリに対応付ける。アプリ内でNASの資格情報を収集しない。

具体的な転送担当、方式、結果通知の形式はOpen。NAS保存の選択だけを根拠に
新しいDockerマウント、サービス、ホストの定期処理を追加しない。
Docker image、ポート8501、既存のマウント、配備と外部公開の境界は維持する。
`/app/downloads` をバックアップ置き場へ流用せず、動画も移動しない。

## 3. Recommended: 対象と検証

| 含めるもの | 対象 |
|---|---|
| 配信記録 | 同接の観測値・集計、配信情報、欠測範囲、カテゴリー変更 |
| コミュニティ | 人物の観測記録、フォロー履歴、メモ |
| チャット・イベント | 保存済み本文、イベント、マーカーとローカルメモ |
| 操作用データ | 配信セット、告知用タグ、自動投稿ルール、コマンド、予想プリセット |
| 非秘密設定 | 表示・機能設定、スキーマやアプリの互換性情報 |
| VOD管理情報 | 動画への参照やジョブ情報。動画本体の存在は復元時に別途確認 |

認証トークン、NAS接続情報、動画本体、稼働中の一時ファイルは対象へ混ぜない。
`/app/data` 全体を無条件に再帰コピーする方法は使わない。

バックアップごとにID、作成理由、作成時刻、データ形式・スキーマ版、サイズ、
ファイルのチェックサム、検証結果を持つ。認証情報やメモ本文を管理用のログへ出さない。
SQLiteの整合性、必要なテーブル、スナップショット内の主要件数を確認する。
NAS側のファイル内容を照合し、ライブDBの現在件数との単純一致は要求しない。
チェックサム一致は転送の検証であり、実際に復元して使えることの検証とは区別する。

## 4. Acceptedの頻度を具体化する運用案

- 配信終了処理で統計とイベントの保存が完了した後、バックアップを予約する。
- 日次はJSTの設定時刻に1回。**合意した初期値は午前4時**とし、設定から変更できる。
- 配信中に日次時刻になっても、オンラインバックアップとして記録と両立させる。
  所要時間・負荷は実装検証で確認する。
- アプリ停止で日次を逃した場合は、再開後に最新状態を1回作る。
  停止中の各日付のデータを再現したバックアップとは表示しない。
- 終了後・日次・手動の要求が重なった場合は並列実行せず、必要なデータを含む
  同じコピーに複数の作成理由を付けてまとめられるようにする。
- 「今すぐバックアップ」を設定画面に用意する。
- 更新・移行・復元の前には、通常のローテーションとは別に作業前バックアップを作る。

### Recommended: 全体停止とバックアップの関係

「全体停止」の意味をそろえ、停止中は日次コピーの作成とNASへの自動転送・再試行も休止する。
バックアップだけが裏で動き続ける例外を作らず、記録や自動実行のワーカー停止契約を維持する。
この選択の代わりに、停止中に変更した設定は手動バックアップまたは再開後までNASに反映されない。

| 操作・状態 | バックアップの動作 |
|---|---|
| 自動投稿だけを無効化 | 日次・配信終了後・NAS転送を継続する |
| 全体停止を要求 | 新しい自動処理を受け付けず、処理中の作成・転送を安全な区切りで休止する |
| 全体停止済み | 自動作成・転送・再試行は休止。検証済みコピーと転送待ち情報を保持する |
| 停止中に手動バックアップ | 他の保守作業がなければ作成・転送を1回行える。記録や自動処理は再開しない |
| アプリ自体が停止 | 自動・手動とも実行できない |
| 全体停止から再開 | 現在状態の確認後に未転送コピーを処理し、休止中に逃した日次分は最新状態で1回作成する |
| 復元・移行の保守中 | 通常バックアップの開始を抑止し、保守処理が管理する作業前コピーだけを扱う |

停止要求と処理の停止完了を分けて表示し、転送途中のファイルを正常コピーへ昇格させない。
外部ステータスの消去はNAS転送の完了待ちにしない。停止したワーカーをバックアップ目的で再起動しない。
停止中の手動操作は排他的な1回の保守処理として扱い、自動ジョブを有効化しない。
ホスト側の転送担当にも休止要求・完了状態を対応付ける必要があり、その通信方式は引き続きOpen。

再開時は過去の日付・配信終了時点のコピーを後付けで作ったことにしない。
待機列が上限なら、検証済みの待機コピーをNASへ転送してから最新状態の作成を試みる。
再開によってチャット送信など他の自動処理を過去分まで再実行しない。

日次と終了後の方式では、NASへ最後に正常保存されたコピー以降のデータは
本体故障時に失われ得る。NAS障害やアプリ停止が続けばその範囲は延びる。
画面では最後にNASへ保存できたコピーのデータ時点を示す。

## 5. Recommended: 世代数と容量

日次・週次・配信終了後の保持数は、利用者が受け入れた初期値を次に示す。
実データ量に応じて設定から変更できる。手動・作業前コピーの整理方法は引き続き詳細案とする。

| 種類 | 保持する候補 |
|---|---|
| 日次 | 直近14日分の成功したコピー。1日1世代 |
| 週次 | 各週の最後に成功したコピーを4週分 |
| 配信終了後 | 最新3世代 |
| 手動・更新前・移行前・復元前 | 自動削除対象外。不要になった時点で手動整理 |

同じコピーが日次・週次・終了後を兼ねる場合、実体は重複させない。
対象のラベルがすべて保持条件を外れたものだけをローテーション候補とする。
新しいNASコピーの検証に成功した後に古い世代を整理し、最後に成功したコピーは
失敗や経過日数だけを理由に消さない。アプリ専用領域の管理対象IDだけを扱う。

無期限保存するチャットは各時点のバックアップに含まれるため、保存量は増える。
世代数を固定しても容量の上限にはならない。使用容量と空き容量、作成見込み容量を
設定画面に示し、圧縮率や重複排除の効果は実測なしに約束しない。

### Recommended: 本体側の待機容量の初期案

以下は測定前の暫定値であり、実際のディスク容量・DBサイズから算出した値ではない。
NASに保持する14日・4週・3世代とは別に、本体側でバックアップが記録領域を圧迫しないための制限とする。

| 項目 | 暫定の初期値・判定 |
|---|---|
| NAS未保存の通常コピー | 最大3世代。作成中の候補も1世代に数え、同じIDの再試行は増やさない |
| 通常バックアップの本体側領域 | 合計10 GiBまで。作成途中・転送待ち・NAS保存済みで本体に残るコピー・一時ファイルを含む |
| 記録用に残す空き | データ保存先ファイルシステムの総容量の10%と5 GiBの大きい方 |
| 実行可否 | 新規候補と作業用領域の見込みを加えても、世代数・容量上限・残す空きをすべて満たすこと |

手動の通常バックアップにも同じ上限を適用する。1コピーだけで上限を超える場合も、
自動で上限を引き上げず「この容量では新しいコピーを作成できない」と表示する。
設定値を既存使用量より小さくしても、既存コピーを即時削除しない。追加作成を止め、超過量を示す。
これらの制限はディスクの事前確保ではなく、他の処理による消費や成長後の記録継続を保証しない。

- 容量不足なら新しいコピーを作らず、理由と見送った時刻・作成要求を記録する。
  コピー未作成の要求は「転送待ちコピー」に数えず、最新状態の再作成要求1件へまとめる。
- 未転送の検証済みコピー、記録本体、チャット本文、動画、他ツールのファイルを自動削除しない。
- NASへ保存・検証できた通常コピーの本体側実体は、使用中でないことを確認して解放できる。
  管理情報とNASの世代は残し、本体側で唯一の正常コピーは失わない。
- NAS復旧時は検証済みの待機コピーを古い順に転送し、本体の空きが戻ったら最新状態を1回作る。
  各コピーのデータ時点を維持し、転送完了時点までの記録を含むとは表示しない。
- コピー作成中も容量と処理量を監視し、上限・残量の条件を満たせなくなったら作成を中断する。
  整理対象はその処理自身の不完全な候補だけとし、検証済みの別コピーを巻き込まない。
- 容量や見込みを確認できない場合は新規作成を見送り、容量不明と表示する。0や無制限とは扱わない。

更新・移行・復元の作業前コピーは通常待機列と分けるが、空き容量の確認を免除しない。
元データ、復元候補、作業前コピー、一時領域を同時に保持する見込みを確認し、確保できなければ
元データの変更前に保守作業を中止する。手動・作業前コピーのNAS上の自動削除除外方針も維持する。

初期設定では実データ量と保存先容量から上記条件を満たすか検証する。
自動実行が一度も成立しない設定を「準備完了」とせず、必要な容量または設定変更を案内する。

## 6. Recommended: NASに保存できない場合

- 配信記録とNAS転送を独立させ、NASの接続待ちが記録や画面応答を止めないようにする。
- NAS不通、容量不足、書き込み不可、転送途中の中断、内容不一致を区別する。
- 有効なローカルコピーがある場合は「本体側で作成済み・NASへの転送待ち」と表示する。
- 再試行は間隔を空け、同じバックアップIDで二重作成を防ぐ。並列再試行はしない。
- NAS接続が戻ったら待機中のコピーの転送を再開する。未完了ファイルは成功扱いしない。
- マウントが外れ、同じパスが本体の通常ディレクトリになった場合にも、
  NASへ保存できたと誤判定しない接続・宛先検証を設ける。
- ローカル側の残量不足も別に表示する。記録側の容量まで尽きた場合に
  「配信記録は継続中」と表示し続けない。
- ライブ画面には新しい失敗と影響を簡潔に表示し、詳細は設定のバックアップ画面へ置く。
  正常時は毎回の成功通知で配信中の画面を埋めない。

## 7. Recommended: 復元

1. 復元候補の日時、含まれる記録、互換性、バックアップ検証状態を確認する。
2. NASから本体側の候補領域へ取得し、内容・整合性・スキーマ互換性を再検証する。
3. 配信外で記録・操作・全ワーカーの書き込みを止め、現在のデータを作業前バックアップへ保存する。
4. 復元対象と戻る時点を示したうえで、検証した候補へ一括切替する。
5. 読み取り確認と必要な移行を行い、失敗した場合は作業前のデータへ戻せるようにする。
6. 接続・認可を確認し、Twitchの現在状態を新しく取得して記録を再開する。

初期実装では別々の履歴を推測でマージせず、選んだ時点への全体復元を基本にする。
復元後は過去の送信待ちチャット、マーカー、予想操作、VODジョブを勝手に再実行しない。
自動実行は停止状態で始め、現在状態との照合後に有効化できるようにする。
外部の配信ステータスはバックアップの過去状態から公開しない。

認証情報はバックアップから戻さず、別に保持した現在の認可を検証するか再認可する。
動画本体の復元は含めず、参照先の存在を再確認する。
以前削除した本文が古いバックアップから戻る場合があることを復元内容に表示する。

アプリが起動できない場合にも利用できる、停止中の復元手順を用意する。
その際も版の適合、既存データの退避、復元後の検証を省略しない。
本資料の作成では実際の復元は実行しない。

## 8. Recommended: 設定画面の構成

| 領域 | 主な表示・操作 |
|---|---|
| 接続 | 配信者・Botの接続と機能別の認可状態、再認可 |
| 記録・機能 | 記録の状態、自動投稿・コマンド・予想の有効化、全体停止 |
| 保存 | 本文の無期限保存、期間を指定した手動削除、データ使用量 |
| バックアップ | NAS保存先の表示、終了後＋日次、日次時刻、世代数、手動実行 |
| 復元 | コピーの選択、内容・互換性の検証、配信外での復元 |

バックアップ画面には「コピー作成中」「NAS転送待ち」「NAS転送中」「検証中」
「NAS保存完了」「失敗・対処が必要」を区別して表示する。
最終成功のデータ時点、NASへの保存完了時刻、次回予定、待機件数、利用容量を示す。
未設定・未確認・値を取得できない状態を、接続正常や容量0として扱わない。
保存先がホスト側管理の場合は参照表示にし、存在しない接続変更機能を見せない。

「自動投稿を止める」と「記録を含む全体停止」を別の操作として説明する。
全体停止後も設定画面へアクセスでき、既存のスナップショット消去契約を守る。
復元を実行する前の確認は、対象と影響を示す製品内の操作として設計する。

今回の設定プレビューで確認できるタブ切替、未保存の変更、削除対象の確認、
配信中・検証失敗時の復元抑止を具体化の基準とする。プレビュー自体は実装ではない。
本資料で追加した全体停止・容量制限の詳細は、次の表示へ反映するRecommendedとして扱う。

| 状態 | 表示案 |
|---|---|
| 全体停止 | 自動バックアップは休止中。手動バックアップは利用可能 |
| NAS不通・本体コピーあり | NAS転送待ち：2件。最後のNAS保存データ：日時 |
| 新規コピーの作成見送り | 本体のバックアップ領域が上限に達したため、新しいコピーを作成できません |
| 記録用の空きが不足 | 記録用の空きを残すため、バックアップ作成を見送っています |
| 記録そのものの保存失敗 | 記録の保存が停止しています。最後に保存できた時刻：日時 |

件数・使用量・上限・残量・見込み量を設定画面に並べ、対処として転送の再試行や容量設定の見直しへつなぐ。
同じ障害の通知は繰り返さず、初回と影響の悪化をライブ画面へ示す。復旧時は状態表示を解消する。

## 9. Openと検証

次に固定するもの:

- NASの専用保存先、接続・転送方式、転送担当と結果を受け取る仕組み。
- 全体停止中のバックアップ休止と、3世代・10 GiB・記録用の空き容量という推奨案の採否。
- 実サイズに基づく容量制限の調整、コピー作成見込みと一時領域の算定方法。
- 手動バックアップの整理、停止中の復元手順、復元検証の実施頻度。
- 設定プレビューへの休止・容量制限表示の反映と、保守操作の排他制御。

実装時に検証するもの:

- 配信中も整合性の取れたコピーが作れ、統計やイベントを失わない。
- 同時要求・再送・再起動でバックアップが重複せず、途中状態から回復できる。
- NAS不通や誤った宛先、容量不足でも記録処理が転送待ちで停止しない。
- 部分転送や内容不一致のコピーを復元候補にしない。
- ローテーションがアプリ専用の管理対象外へ及ばず、最後の正常コピーが残る。
- 全体停止で自動作成・転送・再試行が休止し、公開ステータスの消去を遅らせない。
- 停止中の手動バックアップが記録・投稿ワーカーを起動しない。
- 件数・容量・記録用残量のどれかが不足すれば新規作成を見送り、既存データを削除しない。
- コピー作成途中の容量不足と容量不明を扱い、無制限な作業用ファイルを残さない。
- 上限到達後の再開で待機コピーを転送してから最新状態を保存し、過去時点の欠落を隠さない。
- 復元用の容量不足は元データの変更前に検知し、保全できないまま置き換えない。
- 秘密情報と動画本体が含まれず、元データが変更されない。
- 実際の候補データで復元し、記録・メモ・設定の一致と、外部操作の再実行がないことを確認する。
