# 18. 画面統合と旧データの移行照合

更新日: 2026-09-07

本書はソース実装と、停止済み候補DBで行った実データ照合の記録。本番切替の完了を示さない。
その後の配信セット引継ぎと本番切替の結果は[19](19-production-cutover.md)を参照する。

## 同じFlaskアプリへの画面統合

[アプリ構築関数](../../routes/application.py)に旧画面・フィルター・Blueprint登録をまとめた。
[既存起動入口](../../app.py)は従来どおりその後に旧ワーカーを起動する。
構築関数自体は設定を読まず、旧・新いずれのワーカーも起動しない。

`create_app(v2_container=container)` を明示すると、旧経路を保持して新版の全Blueprintを登録する。
既存の本番起動でこの引数は指定しておらず、本番の新版表示は従来の読み取り専用pilotのまま。
[新版側の登録関数](../../src/twitchbot/web/app.py)は既存コンテナーの差し替えを拒否する。
新版の静的ファイルは `/v2-static`、旧版は `/static` を使う。

[統合テスト](../../tests/test_v2_integrated_host.py)では以下を確認した。

- 旧ルート・HTTPメソッド・endpointがすべて残る。
- 旧analytics画面・VOD進捗・取り消し経路が動作し、不正なIDを拒否する。
- 新版の主要7画面と参照するローカル静的ファイルを表示できる。
- `/api/stream/status` は従来の切り離されたメモリー上の観測だけを読み、Twitchや設定を参照しない。
- 構築だけではワーカーが起動せず、二重登録もできない。

これは画面・API経路の統合段階。新版だけを動かす最終構成で、公開ステータスへ観測を渡す処理、
旧VODの認証・自動取得の担当、旧収集・送信を停止するライフサイクルは引き続き統合が必要。
この構築関数だけで既存の起動構成を置き換えない。

## 変更しない移行元コピー

[コピー作成ツール](../../tools/stage_v2_source.py)は明示された旧dataディレクトリから、
config・viewers・配信index・対象JSONLだけを、新しい専用ディレクトリへコピーする。
既知の認証キーを設定の入れ子も含めて除外する。未知の非機密設定は保留を報告できるよう残す。
元ファイルを変更せず、既存の出力先を上書きしない。動画本体はコピー対象外。

コピー前後のファイル一覧・サイズ・更新情報・内容ハッシュを照合し、変化を検出したら停止する。
途中の出力先には未完了マーカーが残り、候補インポーターの検査を通らない。
1ファイル64 MiB、合計256 MiB、対象4,096ファイルを上限とする。超えた場合は自動で制限を外さない。
これによる稼働中コピーの照合は、最終切替時の停止後スナップショットの代わりにはならない。

```sh
python tools/stage_v2_source.py \
  --source /path/to/legacy/data \
  --target /path/to/new/staged-source
```

## 実データでの候補作成

認証キー3項目を除いた20ファイルを作成し、元データが変化していないことを確認した。
検証用arm64コンテナはネットワーク無効。移行元コピーと動画領域を読み取り専用で渡し、
新しい候補DBだけを専用ローカル領域へ作成した。
旧VODの保存パスと同じ `/app/downloads` 境界で照合した。動画本文を読んだり移動したりしていない。

| 対象 | 読み取り | 候補へ保存 | 保留・確認事項 |
|---|---:|---:|---|
| 配信履歴 | 37 | 37 | 旧版固有の追加項目は別途確認 |
| 同接サンプル | 2,915 | 2,297 | 618件の時刻にタイムゾーンなし |
| 人物 | 145 | 145 | 日付のみの87項目は精度を保って保存 |
| VODメタデータ | 37 | 37 | 実体2件を確認、28件は記録パスに存在せず、7件はパスなし |

[候補インポーター](../../src/twitchbot/migration/importer.py)はv2へ更新した。
空の任意日時は未設定として扱い、フォロー・解除の日付だけの値は正確な時刻へ変換しない。
`legacy_metadata_json.date_only` に日付を残し、旧 `is_follower` も出所を区別できるメタデータとして保持する。
Unix秒の最終確認時刻を受け付け、人物の全保存フィールドを元の変換結果と照合する。
新規受信の正確なフォローイベントや現在の同期結果を、この日付だけの値から生成しない。

## 残る移行項目

- タイムゾーンのない618サンプル。時刻の基準を確認するまでUTCやJSTを仮定しない。
- 配信セット8件・予想プリセット1件・レイアウト3項目。現在の候補インポーターは保留件数を報告する。
- チャット本文491件、視聴者参加・集計イベントなど旧ログの活動データ。サンプルの集計数と本文の移行完了を混同しない。
- VOD実体が見つからない28参照。外部のアーカイブ先を推測して探したり、新たなアーカイブ連携を実装したりしない。
- 未対応の設定・旧固有項目。レポートの `unknown:*` に件数を残し、黙って移行済みにしない。
- 日付精度を保持した人物メタデータを新版の履歴画面へ表示する処理。

候補レポートの `verified` は、候補へ保存した範囲が照合できた意味。
保留の解消、全機能の移行、本番切替を許可する状態とは区別する。
実機のパス・資格情報・人物名・配信IDをこの資料へ記録しない。

## 検証結果

- Windows全体テスト: 431件成功、15件スキップ。
- Pi/arm64全体テスト: 446件成功、スキップなし。
- 実データ候補: 変換済み人物の各フィールド・集計・移行元不変を照合。
- 文書リンク・コードフェンス・`git diff --check` は成功。
- 旧Botの稼働・health・起動時刻・再起動回数が変化していないことを確認。

検証用コンテナは終了済み。元データ、失敗コピー、照合済みコピー、各候補DBは上書きせず分けて保持した。
本番のアプリ・依存関係・配備・data/downloadsマウントを更新したという意味ではない。
